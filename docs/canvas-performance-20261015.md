# 画布交互性能修复 · 2026-10-15

拖动节点、群组和调整尺寸时，旧实现会在每个 pointermove 中保存整个项目并重建全部节点与连线。缩放和平移也会逐事件写 localStorage。节点及输入槽位增多后，重复布局测量、DOM 构建和序列化累积为明显卡顿。

## 修复

- 指针输入按 requestAnimationFrame 合并，只使用本帧最后的位置；松手时立即处理最终坐标。
- 移动和调整尺寸直接更新已有节点的 CSS 变量，图片与视频 DOM 保持不变。
- 缓存节点尺寸和输入端口相对位置；尺寸变化由 ResizeObserver 定向失效。测量先读后写，移动时只修改相关连线的路径。
- 连线预览只更新预览路径，不重建整张图的边。
- 拖动完成保存一次；缩放停止 200ms 后保存。取消拖动、失焦、页面隐藏和关闭时补齐待处理位置与保存。
- 框选采用节点几何信息命中；拖动前记录撤销快照，保持撤销/重做正确。

## 对照结果

独立 Chrome 临时配置和临时静态服务，80 个混合节点、80 条连线。每个拖动场景发出 96 次移动事件，分为 24 组、每组 4 次；不读取真实用户项目，不访问生成接口。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 节点拖动：全画布重建 | 96 | 0 |
| 节点拖动：保存 | 96 | 1 |
| 节点拖动：矩形测量 | 30,818 | 27 |
| 群组拖动：全画布重建 | 97 | 0 |
| 调整尺寸：全画布重建 | 97 | 0 |
| 调整尺寸：矩形测量 | 30,976 | 75 |
| 平移：保存 | 96 | 1 |
| 连续 60 次滚轮输入：保存 | 60 | 1 |

测得节点拖动的 P95 帧间隔由约 778ms 降至约 41ms；这属于上述压力场景的无界面浏览器测量，受机器负载影响，不代表用户页面恒定帧率。更稳定的回归判据是重建次数、保存次数、节点身份和几何正确性，不按机器相关的耗时设置测试门槛。

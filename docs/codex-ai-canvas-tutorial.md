# 用 Codex 从 0 制作 AI 无限画布系统教学文档

这份文档不是普通产品说明，而是一份给学员看的制作流程指南：如何用 Codex 逐步做出一个类似 TapNow / Huobao Canvas 的 AI 工作流画布系统。

核心方法是：先做可交互原型，再接后端 API，再补工作流能力，最后反复根据真实使用问题修交互和数据存储。

## 一、最终要做成什么

这个项目最终形成的是一个前端加后端结构的 AI Canvas 系统。

前端负责：

- 无限画布、节点拖拽、缩放和平移
- 文本节点、LLM 节点、文生图节点、图像结果节点、视频节点
- 节点之间连线形成工作流
- 右键菜单、框选、群组、模板、项目管理
- 图片预览、保存、节点尺寸调整

后端负责：

- 保存 API Key，不让前端暴露密钥
- 转发文本、图像、视频 API 请求
- 支持不同服务使用不同 Base URL 和 API Key
- 代理图片地址，解决部分图片跨域加载问题

## 二、制作顺序总览

推荐按这个顺序带学员做：

1. 先做静态无限画布原型
2. 再做节点、连线、拖拽、缩放
3. 再做 AI 工作流节点类型
4. 再拆成前后端结构
5. 再接入真实图像/视频 API
6. 再做右键菜单、框选、群组
7. 再做模板库和项目管理
8. 再处理真实使用里的 bug
9. 最后补图片预览、保存、节点缩放等体验细节

不要一开始就要求 Codex 一次性做完整系统。这样的项目一定要分阶段推进，每一阶段都有可验收的画面和交互。

## 三、第一阶段：做可看的静态画布

目标：先做一个能打开的页面，看起来像 AI 工作流画布。

提示词示例：

```text
我要做一个类似 TapNow.ai 的 AI 无限画布原型。
先只做前端静态版本，不接真实 API。
页面需要有画布、节点、连线、左侧工具栏、顶部标题栏。
节点类型包括：提示词节点、文生图配置节点、图像生成结果节点、视频生成配置节点。
请直接在当前项目里实现，可以用原生 HTML/CSS/JS。
```

验收标准：

- 页面能打开
- 节点视觉清晰
- 连线能看出工作流方向
- 不需要 API，不需要复杂状态

这一阶段不要纠结所有功能。先让学员看到“画布系统长什么样”。

## 四、第二阶段：让画布能操作

目标：把静态图变成可操作的画布。

提示词示例：

```text
请完善画布操作逻辑：
1. 鼠标滚轮控制缩放
2. 鼠标在空白区域按住拖拽，可以上下左右平移画布
3. 节点可以拖拽移动
4. 选中节点后按 Delete 可以删除
5. 节点移动时连线要跟随更新
```

验收标准：

- 滚轮缩放自然
- 空白处拖拽不会误拖节点
- 节点移动后连线端点对齐
- Delete 删除节点时相关连线一起删除

常见补充提示：

```text
现在节点和连线端点没有对齐，请修复。要求连线从节点左右两侧的连接点出发，不要从节点中心穿过去。
```

## 五、第三阶段：实现节点连线交互

目标：用户可以像工作流工具一样从一个节点拖线到另一个节点。

提示词示例：

```text
请修复/增加节点之间的连线交互：
1. 每个节点左右两侧有输入/输出连接点
2. 从输出点拖拽到输入点可以建立连线
3. 拖拽过程中要实时显示预览线
4. 连接完成后保存到状态里
5. 鼠标悬停连线时高亮，双击连线可以断开
```

验收标准：

- 拖线时能实时看到线
- 松开到目标节点后生成正式连线
- 悬停线高亮
- 双击线删除该连线

这一步很关键，因为 AI Canvas 的核心不是单个节点，而是节点之间的关系。

## 六、第四阶段：拆成前端加后端

目标：不要把 API Key 放在前端。真实项目一定要有后端代理。

提示词示例：

```text
这个项目要改成前端加后端结构。
前端仍然是静态页面，后端用 Node.js。
API Key 必须只放在后端环境变量里，前端不能保存或发送用户输入的 key。
请增加 server/server.js，提供：
GET /api/status
POST /api/images/generations
POST /api/video/create
POST /api/video/query
并让前端调用这些后端接口。
```

验收标准：

- `npm run dev` 能启动服务
- 页面通过 `http://127.0.0.1:8787` 打开
- 前端不直接请求第三方 API
- API Key 不写死在 JS 里

教学重点：

告诉学员：只要涉及密钥，就必须进入后端。前端只负责发业务请求，后端负责带密钥转发。

## 七、第五阶段：接入真实 API

目标：图像生成、文本润色、视频生成开始调用真实接口。

提示词示例：

```text
请根据这个 API 文档接入图像生成接口：
文档地址：xxxx
要求：
1. API Key 只从后端环境变量读取
2. 前端点击文生图节点的“生成图片”按钮后调用后端
3. 返回图片后自动填入当前工作流里的图像生成结果节点
4. 不要每次都新建结果节点，如果当前工作流已有结果节点就更新它
5. 错误信息显示在结果节点里
```

验收标准：

- 点击生成后节点进入 loading
- 成功后结果节点显示图片
- 失败后节点显示可读错误
- 不重复创建无用结果节点

常见问题：

不同模型参数可能不一样。例如 `gpt-image-1` 和 Seedream 的尺寸、字段并不完全相同。遇到这种问题，不要只说“API 报错”，要让 Codex 对照文档检查请求体。

补充提示：

```text
图像接口报错了。请不要直接猜测，请检查当前前端提交的请求参数、后端转发的请求体，以及该模型在文档中要求的字段是否一致。
```

## 八、第六阶段：设置页和高级 API 配置

目标：让用户可以在界面里配置不同能力的模型和接口。

提示词示例：

```text
设置里面需要支持高级设置：
1. 文本、图像、视频可以分别设置 Base URL、API Key、默认模型
2. 如果某一项没有单独配置，就回退到通用 Base URL 和通用 API Key
3. 前端只显示 key 是否已配置，不显示真实 key
4. 配置保存到后端本地文件，加入 .gitignore
5. 节点里的模型下拉选项要和设置里的默认模型保持一致
```

验收标准：

- 设置页可以编辑
- 保存后刷新仍然存在
- 不在前端暴露密钥
- 节点模型和设置模型逻辑一致

教学重点：

这里可以给学员讲“产品逻辑一致性”：如果节点里可以选很多模型，设置里也应该提供对应选择，而不是只能手动输入一个模型名。

## 九、第七阶段：补齐画布编辑能力

目标：从 demo 变成真正可用的编辑器。

推荐按顺序增加：

1. 右键菜单
2. 框选节点
3. 群组
4. 群组标题栏拖拽
5. 节点尺寸缩放
6. 图片预览和保存

右键菜单提示词：

```text
请给画布增加鼠标右键菜单：
1. 禁用浏览器默认右键菜单
2. 空白区域右键显示新建节点、刷新节点等菜单
3. 节点上右键显示复制、删除、刷新等菜单
4. 图片节点右键显示预览图片、保存图片、图生图、生视频
```

框选和群组提示词：

```text
请增加 CTRL + 鼠标左键框选节点。
框选多个节点后，右键菜单显示“群组化”。
群组后生成一个群组容器，群组顶部有标题栏。
只允许拖拽标题栏移动整个群组，群组其它区域不要拖拽，避免误操作。
```

节点缩放提示词：

```text
所有节点右下角增加一个小型缩放手柄。
拖拽手柄可以调整节点宽高，尺寸保存到 node.data.width 和 node.data.height。
手柄要像 textarea 原生缩放角标一样小，不要影响美观。
文本节点内部 textarea 不需要单独缩放，节点多大，文本框就撑多大。
```

图片预览提示词：

```text
图像生成结果节点需要增加图片预览和保存：
1. 单击图片打开大图预览弹窗
2. 右键图片显示“预览图片/保存图片”
3. 弹窗里也有保存图片按钮
4. 如果图片存储在 IndexedDB，也要能正常预览和保存
```

## 十、第八阶段：项目管理和模板库

目标：让用户不只是做一次工作流，而是能保存、复用、导入导出。

项目管理提示词：

```text
请在当前页面前面增加一个上一级项目管理页面。
用户打开应用后先看到项目列表，可以新建、打开、重命名、复制、删除项目。
每个项目保存一个完整工作流。
打开项目后进入画布编辑器。
```

模板库提示词：

```text
用户可以把当前工作流保存成模板。
模板库需要支持：
1. 新建模板分组
2. 保存当前工作流为模板
3. 从模板加载工作流
4. 导出模板 JSON
5. 把 JSON 拖入编辑窗口后加载工作流
```

验收标准：

- 项目和模板分开
- JSON 可以导出
- JSON 可以拖入导入
- 导入时要校验节点、连线、群组是否有效

教学重点：

告诉学员：真正的工具产品必须有“保存、复用、迁移”。没有项目管理和模板库，只是一个一次性 demo。

## 十一、第九阶段：处理真实使用中的 bug

这个项目里遇到的典型问题，非常适合拿来教学。

### 1. 节点不对齐

提示词：

```text
节点和连线端点不对齐，请检查节点尺寸、连接点位置、SVG 坐标转换和缩放状态下的坐标计算。
修复后要求不同缩放比例下依然对齐。
```

### 2. 拖拽画布异常

提示词：

```text
现在鼠标在空白处拖拽画布，第一次正常，第二次会出现鼠标变红叉、松开后画布仍跟随移动的问题。
请检查 pointer capture、pointerup、pointercancel、dragstart 和浏览器默认拖拽行为。
修复后要求每次拖拽都能正确开始和结束。
```

### 3. 图片保存超出 localStorage 额度

提示词：

```text
图像生成返回成功，但节点显示 localStorage quota exceeded。
请检查是否把 base64 大图直接保存进 localStorage。
要求改成大图片存 IndexedDB，项目 JSON 只保存短引用。
同时 localStorage 保存失败不应该被误显示成图像生成失败。
```

教学重点：

AI 生成图片经常是大体积 base64。不要把大资源塞进 localStorage。结构化项目数据可以放 localStorage，大文件应该放 IndexedDB、对象存储或服务器。

## 十二、如何写好给 Codex 的提示词

### 好提示词结构

建议学员按这个格式写：

```text
我要实现【功能目标】。
当前问题是【现象】。
请检查【可能相关模块】。
要求：
1. ...
2. ...
3. ...
验收标准：
1. ...
2. ...
不要做：
1. ...
```

### 示例：功能型提示词

```text
我要给画布增加节点群组功能。
要求：
1. CTRL + 鼠标左键可以框选多个节点
2. 框选后右键菜单出现“群组化”
3. 群组后显示一个带标题栏的容器
4. 只能拖拽标题栏移动整个群组
5. 群组可以重命名和解散
请保持现有节点拖拽和连线逻辑不受影响。
```

### 示例：排错型提示词

```text
现在图像生成失败，页面显示错误。
请不要直接改 UI，请先检查：
1. 前端发给后端的请求体
2. 后端转发给第三方 API 的请求体
3. 当前模型在接口文档中要求的字段
4. 浏览器控制台和服务端日志
最后给出原因并修复。
```

### 示例：体验优化型提示词

```text
节点右下角缩放手柄太大，影响美观。
请改成类似 textarea 原生 resize 的小角标。
同时文本节点内部 textarea 不需要单独缩放，节点多大，文本框就多大。
不要影响其它节点的缩放功能。
```

## 十三、课堂练习安排

可以把课程拆成 6 次练习。

第一课：静态画布

- 做页面布局
- 做节点卡片
- 做 SVG 连线

第二课：画布交互

- 拖拽节点
- 缩放和平移
- 删除节点

第三课：连线和工作流

- 连接点
- 拖拽连线
- 连线预览
- 双击断线

第四课：后端和 API

- Node 后端
- API Key 放后端
- 图像生成
- 错误显示

第五课：编辑器能力

- 右键菜单
- 框选
- 群组
- 节点缩放

第六课：产品化

- 项目管理
- 模板库
- JSON 导入导出
- 图片预览保存
- 大图片 IndexedDB 存储

## 十四、最终项目结构建议

```text
project/
  public/
    index.html
    styles.css
    app.js
  server/
    server.js
  docs/
    codex-ai-canvas-tutorial.md
  package.json
  .env.example
  .gitignore
  README.md
```

前端不要保存密钥。后端不要直接把密钥返回给前端。大文件不要塞进 localStorage。

## 十五、给学员的核心心法

1. 不要一次性让 Codex 做完整产品，要按阶段推进。
2. 每次提示词都写清楚“目标、约束、验收标准”。
3. 遇到 bug 不要只说“坏了”，要描述现象、触发步骤、期望行为。
4. 接 API 时先保护密钥，再考虑功能。
5. 做工作流产品时，节点、连线、状态保存三件事必须稳定。
6. 做 AI 产品时，真实返回数据往往很大、很慢、格式不稳定，要预留错误处理。
7. Codex 很适合做“边用边改”的产品，关键是每次只让它解决一个明确问题。

## 十六、推荐给 Codex 的总启动提示词

如果学员从 0 开始，可以直接用下面这段：

```text
我要用前端加后端做一个 AI 无限画布工作流系统，类似 TapNow.ai。
请先实现一个可运行的原型，不接真实 API。
技术要求：
1. 前端使用原生 HTML/CSS/JS
2. 后端后续使用 Node.js，但第一步可以先只做前端
3. 页面包含无限画布、节点、连线、工具栏
4. 节点包括提示词、文生图配置、图像结果、视频配置、视频结果
5. 支持节点拖拽、画布缩放、画布平移
6. 先保证可运行和可交互，不要一次性做所有高级功能
请直接在当前项目中实现，并告诉我如何打开预览。
```

完成第一版后，再逐步追加本文档里的阶段提示词。
